AI and advisory

AI in engineering work, on terms an engineer can sign

I advise infrastructure and asset-intensive clients on digital, data and AI work, and my group builds and tests the methods. Client names and project data stay with the clients.

Method

Rules first, then wider use

Standards first

Written rules before any tool is used

AI must not invent data, confidence is stated, people check every output, client data stays out of public services, and AI-written code is reviewed before use. Wider use comes second.

rules firstclient data protected

Division of work

AI drafts, the engineer decides and signs

AI produces first drafts and repeated checks; the engineer reviews, decides and signs. In my group I specify the requirements, review the code and accept the results; implementation is by the team and AI coding agents.

human reviewengineer signs

Audit trail

Evidence that a result can be trusted

On safety-critical assets, a model is worth as much as the evidence that it can be trusted. We build that in: independent re-computation, signed audit ledgers, benchmark audits, and written records of tests that have not yet passed. Contractual targets are kept apart from achieved results.

independent re-computationfailures recorded

Start small

Agree the decision, then pilot on one work package

Scope starts from the decision the work must support. Acceptance, data ownership and whether any AI tool may see client data are written down before work begins. I would then test the approach on one work package before wider use, and hand over methods and standards so the client can continue alone.

acceptance agreed firstone work package
